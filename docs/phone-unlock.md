# 用手机指纹解锁电脑（Wi-Fi / 蓝牙）

手机上打开“电脑解锁”App → 连上电脑（同一局域网走 Wi-Fi，否则走蓝牙 BLE）→ 显示电脑名、用户名、锁屏截图 →
按指纹 → 电脑解锁。指纹只在手机里比对，电脑收到的是手机用“必须先过指纹才能用”的密钥做的签名。

另外两个功能：**一键锁屏**（App 里点一下锁住电脑，不用指纹）和**离开自动锁屏**（可选，类似 Windows 的“动态锁”：
手机和电脑保持蓝牙连接，手机走远、蓝牙断开超过设定秒数没连回来，电脑自动锁屏；回来时不会自动解锁）。

## 组成

| 部分 | 运行身份 | 作用 |
|---|---|---|
| `hisi-bio-unlock`（已有的锁屏指纹 / 人脸服务） | root，无网络 | 保存配对的手机、出一次性挑战、验签、调 logind `UnlockSession`、截锁屏图（降权到桌面用户跑 grim） |
| `hisi-phone-link` | 专用用户 `hisi-phone` | 只做收发：TCP / UDP 47390（Wi-Fi）和 BLE GATT 外设；把请求经 D-Bus 转给上面的服务，自己不碰密钥 |
| `hisi-phone`（命令） | root | `pair` 显示配对二维码、`list` 列出、`unpair` 删除、`rename <ID> <别名>` 设手机别名（空串恢复手机原名） |
| 控制中心插件 `phoneunlock.so` | 桌面用户 | deepin 25 “账户 → 登录方式 → 手机解锁”：不碰命令行也能配对、设别名、删除、锁屏试试；配对要过 polkit（输自己的登录密码） |
| Android App `org.hisi.phoneunlock` | 手机 | 扫码配对、连接、显示电脑信息、指纹签名、一键锁屏；离开自动锁屏用一个前台服务保持蓝牙连接 |

## 安全模型

- **配对**（电脑已登录时 `sudo hisi-phone pair`）：电脑生成 16 字节随机配对码，和电脑 ID、IP、蓝牙地址一起放进二维码（3 分钟有效，用一次就作废）。
  手机在 Android Keystore 里生成 EC P-256 密钥，设为每次使用都要过强生物识别（指纹），把公钥连同用配对码算的 HMAC 发给电脑。
  配对码只经过摄像头，不在网络 / 蓝牙上传输；中间人不知道配对码就换不掉公钥。
  配对成功后双方各自由配对码导出一个共享密钥 S（手机存在 App 私有存储，电脑存在 `/var/lib/hisi-bio/phones.ini`，root 0600）。
- **解锁**：手机发 HELLO → 电脑出 32 字节随机挑战 cn（120 秒有效、只能用一次），并用 S 派生的会话密钥加密电脑信息一起发回
  （手机能解开就说明对方是配对过的那台电脑；旁听的人看不到截图和用户名）→ 用户按指纹 → Keystore 用私钥签
  “电脑 ID + 手机 ID + cn + 手机随机数” → 电脑验签通过才解锁。截获的签名不能重放。
- **多台手机**：同一个电脑用户最多绑定 5 台（`PHONES_PER_USER`），每台各有自己的密钥和共享密钥，互不影响，删掉一台不影响别的。
  满了以后新手机配对回 `ERR 13`；同一台手机重新配对（同一个手机 ID）不算新增，可以照常替换旧记录。
- 签名错 5 次，该手机暂停 5 分钟。指纹数据、私钥都不出手机；手机新录入指纹后 Keystore 密钥自动失效，需要重新配对。
- 截图只在该用户的会话确实锁着时给，只给锁屏画面。
- **锁屏不要指纹**：锁屏不泄露任何东西，只要证明是配对过的那部手机（用 HELLO 的会话密钥算 HMAC）就行，防的是局域网里别人乱锁。
- **离开自动锁屏**只会锁、不会解锁。能让电脑“误锁”的情况（手机关蓝牙、App 被系统清掉、人为干扰蓝牙）最多造成一次锁屏；
  手机重新靠近也不会自动解锁，解锁照样要过指纹。开关只能由配对的手机发（同样要会话密钥的 HMAC），电脑只记在内存里。

## 控制中心插件（deepin 25）

入口在 “账户 → 登录方式 → 手机解锁”（`/usr/lib/<multiarch>/dde-control-center/plugins_v1.0/phoneunlock/`）。
列表显示绑定的手机（在线状态、配对时间），每台可以设别名、删除；“添加手机…”会先弹 polkit 认证框
（action `org.hisi.bio-unlock.pair-phone`，输自己的登录密码），过了才显示配对二维码——和 `sudo hisi-phone pair` 的是同一个码。
插件经系统总线 `org.hisi.BioUnlock1.User` 跟服务说话，服务按调用者 uid 只让他看、改自己的手机；D-Bus 策略在
`/etc/dbus-1/system.d/org.hisi.BioUnlock1.conf`。

- **别名**：只影响电脑这边显示什么（手机列表、锁屏提示、日志）。手机配对时上报名永远保留，存 `phones.ini` 的 `name=`，
  别名存 `alias=`（显示名 = 别名优先，没有别名用上报名）。设别名、清除都不用重新配对。
- **排障**：点“添加手机”没反应、日志反复“没通过认证”，多半是 polkit 认证 agent 注册错了会话（ddm/会话重启过几轮之后常见）：
  `journalctl -t polkitd` 看 agent 注册在哪个 `unix-session`，控制中心进程环境 `XDG_SESSION_ID` 是哪个，两者要一致；
  不一致就把 agent 进程迁进 `session-<id>.scope` 再拉起（agent 按 cgroup 归属选会话，认 `XDG_SESSION_ID` 没用）。

## 协议（版本 1）

### 通用

- 消息是一行 UTF-8 文本，以 `\n` 结尾，字段之间一个空格。二进制字段用标准 Base64（带 `=` 补齐，不换行）。
- 手机发出的一行不超过 4 KiB；电脑回的一行不超过 512 KiB（截图）。
- `pc_id`：电脑 ID，32 个小写十六进制字符（16 字节随机，电脑首次运行生成）。
- `phone_id`：手机 ID，32 个小写十六进制字符（16 字节随机，手机配对时生成，每台电脑一个）。
- 下文 `‖` 是字节拼接，`0x00` 是一个零字节，字符串都按 UTF-8 字节、不带结尾零。
- `HMAC(k, m)` = HMAC-SHA256；`box(k, aad, p)` = `iv(12 字节随机) ‖ AES-256-GCM(k, iv, aad, p) 的密文 ‖ 16 字节 tag`
  （Java `Cipher("AES/GCM/NoPadding")` + `GCMParameterSpec(128, iv)` 的 `doFinal` 输出本来就是 密文‖tag）。aad 是 ASCII 字符串。
- 出错时电脑回 `ERR <code> <msg_b64>`，`msg` 是给人看的中文说明。`code`：

| code | 含义 |
|---|---|
| 0 | 成功（不会出现在 ERR 里） |
| 1 | 手机没配对 / 已被删除（App 应提示重新配对） |
| 2 | 该用户没有登录图形会话 |
| 3 | 签名不对 |
| 4 | 挑战过期或已用过（重新 HELLO） |
| 5 | 失败太多，暂停一会儿 |
| 6 | 电脑上没有在配对（二维码过期） |
| 7 | 配对校验失败（配对码不对） |
| 8 | 电脑没有锁屏（截图不给） |
| 9 | 忙（另一台手机正在用蓝牙连接） |
| 10 | 电脑内部错误 |
| 11 | 请求格式不对 |
| 12 | 电脑上的解锁服务没运行 |
| 13 | 该用户已绑定 5 台手机（上限），新手机要先在电脑上删一台（只出现在 PAIR 的回复里） |

### 配对二维码

```
hisiphone://pair?v=1&id=<pc_id>&c=<code>&h=<主机名>&u=<用户名>&ip=<ip1,ip2,...>&p=47390&bt=<蓝牙地址>
```

- `c`：16 字节配对码，Base64url 无补齐（22 字符）。`h`、`u` 做 URL 百分号编码。`ip` 是电脑当前的 IPv4 列表（可能为空），
  `bt` 形如 `24:E9:CA:8D:D4:52`（可能为空）。

### 消息

**PING**（可选，确认连到的是哪台电脑）

```
→ PING
← PONG <pc_id>
```

**配对**

```
→ PAIR 1 <phone_id> <name_b64> <pub_b64> <mac_b64>
← PAIROK <mac2_b64>
```

- `name`：手机名，UTF-8，不超过 64 字节，不含控制字符。App 默认自动取：先取“设备名称”（设置里能看到、能改的名字，如 `nova 10`；
  华为 `unified_device_name`、其它厂商 `device_name`），没有再取设备型号（营销名，如 `Xiaomi 14`，厂商系统属性），再取蓝牙名称，
  都取不到才用认证型号 `Build.MODEL`；设备名称等于认证型号的（很多手机的默认值）视为没有。配对页可以改。配对后在电脑上设别名
  （`hisi-phone rename <ID> <别名>`，空串清除；或控制中心里点“别名”）——别名只管电脑这边显示，这个名字保留不动。`pub`：公钥的 X.509 SubjectPublicKeyInfo DER（Java `PublicKey.getEncoded()`）。
- `T = "hisi-phone-pair-v1" ‖ 0x00 ‖ pc_id ‖ 0x00 ‖ phone_id ‖ 0x00 ‖ name ‖ 0x00 ‖ pub`
- `mac = HMAC(code, T)`，`mac2 = HMAC(code, "hisi-phone-pair-ok-v1" ‖ 0x00 ‖ T)`。手机必须核对 mac2，不对就当配对失败。
- 成功后双方：`S = HMAC(code, "hisi-phone-secret-v1" ‖ 0x00 ‖ pc_id ‖ 0x00 ‖ phone_id)`（32 字节）。手机保存 S、丢掉 code。

**HELLO（每次解锁先发）**

```
→ HELLO 1 <phone_id> <pn_b64>
← CHAL <cn_b64> <box_b64>
```

- `pn`：手机每次新生成的 16 字节随机数。`cn`：电脑的 32 字节挑战。
- 会话密钥 `ks = HMAC(S, "hisi-phone-session-v1" ‖ 0x00 ‖ cn ‖ pn)`。
- `box = box(ks, "hisi-info-v1", info)`，`info` 是若干行 `key=value\n`：

| key | 值 |
|---|---|
| `user` | 配对的用户名 |
| `realname` | 用户全名（可能为空） |
| `host` | 主机名 |
| `session` | `1` 该用户有本地图形会话，`0` 没有（此时不能解锁） |
| `locked` | `1` 确认在锁屏，`0` 没锁或不确定（不确定时仍可尝试解锁） |
| `locked_for` | 已锁屏秒数（`locked=1` 时才有） |
| `shot` | `1` 可以要截图 |
| `away` | 离开自动锁屏：`0` 没开，否则是电脑记着的等待秒数（见 AWAY） |

  解不开（tag 校验失败）就说明对方不是配对的那台电脑，App 应断开并报错。
- 电脑给每台手机最多同时留两个没用过的挑战（App 的后台蓝牙连接和解锁界面可能各要一个），再多就挤掉这台手机最旧的那个。

**截图（可选，HELLO 之后）**

```
→ SHOT <width> <mac_b64>
← SHOTOK <box_b64>
```

- `width`：想要的宽度（像素，十进制，电脑会限制在 288～960 之间）。Wi-Fi 建议 720，蓝牙建议 432。
- `mac = HMAC(ks, "hisi-phone-shot-v1" ‖ 0x00 ‖ width 的十进制 ASCII)`。
- `box = box(ks, "hisi-shot-v1", JPEG 数据)`。截一次大约要 1 秒。

**解锁**

```
→ UNLOCK <sig_b64>
← OK
```

- `U = "hisi-phone-unlock-v1" ‖ 0x00 ‖ pc_id ‖ 0x00 ‖ phone_id ‖ 0x00 ‖ cn ‖ pn`（cn、pn 是原始字节）。
- `sig` = Keystore 私钥 `SHA256withECDSA` 对 U 的签名（DER，Java `Signature.sign()` 的输出）。
- 不管成败，这个 cn 都作废；要重试就重新 HELLO。

**锁屏（HELLO 之后，不用指纹）**

```
→ LOCK <mac_b64>
← OK
```

- `mac = HMAC(ks, "hisi-phone-lock-v1")`（只有这个标签，后面没有零字节）。
- 电脑调 logind `LockSession` 锁该用户的本地图形会话；已经锁着也回 `OK`；该用户没登录回 `ERR 2`。
- 和 UNLOCK 一样，不管成败这个 cn 都作废。

**离开自动锁屏（HELLO 之后，只能走蓝牙）**

```
→ AWAY <grace> <mac_b64>
← OK
```

- `grace`：十进制、无前导零。`0` = 关闭；`5`～`600` = 开启：**这条蓝牙连接**断开后，`grace` 秒内这部手机没有重新连上并再发一次
  AWAY（任何非 0 值），电脑就锁屏。其他值回 `ERR 11`。
- `mac = HMAC(ks, "hisi-phone-away-v1" ‖ 0x00 ‖ grace 的十进制 ASCII)`。cn 不作废（同一个 HELLO 之后还可以接着发别的）。
- 走 Wi-Fi（TCP）发 AWAY 回 `ERR 11`：TCP 断开电脑感知不到也不及时，只认蓝牙链路的断开（BlueZ 的 `Device1.Connected` 变 false，
  手机走远时由蓝牙的连接监督超时触发，Android 上一般 5 秒）。
- 锁过一次（或手机发了 `AWAY 0`）就算关了，手机连回来再发 AWAY 重新开启。电脑自己关蓝牙、`hisi-phone-link` 重启都不会锁屏，
  只是暂时失效；`hisi-bio-unlock` 重启会忘掉开关。所以 App 连着时每 5 分钟重发一次 HELLO + AWAY。
- 想关掉时，手机必须**先发 `AWAY 0` 再断开**，否则电脑会把这次断开当成离开。

### Wi-Fi

- TCP 47390：一条连接是一个会话，可以连续发多行（如 HELLO → SHOT → UNLOCK）。空闲 90 秒电脑断开。
- 发现（UDP 47390）：手机向 `255.255.255.255:47390` 和二维码里的每个 IP 发 `HISI-PHONE? <pc_id>\n`，
  电脑（pc_id 对得上时）单播回 `HISI-PHONE! <pc_id> <tcp端口>\n`，手机用回包的源地址连 TCP。
- 手机和电脑在同一个局域网（同一网段、路由器没开 AP 隔离）时，靠 UDP 发现或二维码里的 IP 直连。
- 不在同一个局域网时可以经 Tailscale：电脑装 Tailscale 后，`hisi-phone pair` 的二维码会带上 `tailscale0` 的地址
  （`ip=` 里的 100.x.x.x），手机装 Tailscale 登录同一账号即可直连，旧配对在 App 里“编辑额外地址”补上 100.x。
  App 只把局域网地址绑到 Wi-Fi（私网、链路本地、IPv6 ULA），回环、Tailscale（100.64.0.0/10、fd7a:115c:a1e0::/48）和公网
  地址走系统默认路由；对这类远端地址连接超时放宽到 3 倍、PING 放宽到 2 倍。UDP 广播发现过不了 Tailscale，靠直连地址。
  离开自动锁屏（AWAY）只认蓝牙，远程用不了。

### 蓝牙 BLE

- 电脑是 GATT 外设，一直在广播（可连接，带服务 UUID）。手机用二维码里的蓝牙地址直接 `connectGatt(TRANSPORT_LE)`
  （等“连上”最多 12 秒，连上后找服务等再另给至少 6 秒），连不上再扫描：带服务 UUID 的，或地址就是二维码里那个的。
- L540 的 5.4 内核（扩展广播）有三处毛病，电脑端照着绕：
  - 广播实例默认只播 2 秒、到期后内核不再重开 → 设 `Duration` 60 秒，`hisi-phone-link` 到期后注销再注册续上；
  - 内核“停止全部广播”这块控制器不认，注销后旧实例照播到时长用完，期间重新注册被拒（`Command Disallowed`）
    → 续期要等旧实例到期，见 `hisi-phone-link.c` 里 adv_renew 前的说明；
  - 广播数据只写给句柄 0，BlueZ 的实例在句柄 1 → **空中的广播不带服务 UUID**，手机按 UUID 扫不到，只能按蓝牙地址连
    （二维码和配对记录里都有地址，不影响使用）；广播间隔也写死 1.28 秒，所以手机蓝牙连上要 1～6 秒。
- 服务 `5a3f0001-4c6e-4f1b-9d2a-7e8b1c0d4f60`
  - RX `5a3f0002-4c6e-4f1b-9d2a-7e8b1c0d4f60`：write / write-without-response，手机 → 电脑
  - TX `5a3f0003-4c6e-4f1b-9d2a-7e8b1c0d4f60`：notify，电脑 → 手机（手机要先写 CCCD `0x2902` 打开通知）
- 消息格式和 TCP 完全一样（文本行）。手机先 `requestMtu(517)`，按 `MTU-3` 字节分片写 RX（等上一片写完回调再写下一片），
  电脑按 `MTU-3`（最多 512）字节分片通知，双方各自拼到 `\n` 为止。
- 一个 BLE 连接是一个会话；同一时间只服务一台手机，别的手机写入会被拒绝。
- 离开自动锁屏时 App 的前台服务一直连着（发完 AWAY 后请求低功耗连接参数，不再说话），解锁界面再连同一台电脑时
  Android 复用同一条蓝牙链路（两个 GATT 客户端）。电脑的通知会发给链路上所有订阅了的客户端，所以 App 里两边不同时说话：
  解锁界面用着蓝牙连接时后台服务不发请求，每次请求前后台服务先丢掉收到的无关回复。
  手机走远断开后，后台服务先直连 20 秒，连不上就改用系统的后台自动重连（`autoConnect`，省电，电脑回到范围内才连上；
  扫描频率低，实测电脑回来后约 1 分钟才连上）。手机蓝牙一打开就立刻重连（监听 `ACTION_STATE_CHANGED`），
  所以关蓝牙几秒再打开赶得上 15 秒的宽限；蓝牙关掉时放弃正在进行的连接（系统蓝牙重启后旧的 autoConnect 不会再回调）。
- 华为 / 荣耀（EMUI）默认不让侧载 App 自启动：开机广播、App 更新后的 `MY_PACKAGE_REPLACED` 都收不到（实测更新后服务没起来，
  电脑按“手机离开”锁了屏）。要在 设置 → 应用 → 应用启动管理 里把 App 改成手动管理、打开全部开关；App 的设置框里有这段提示。
